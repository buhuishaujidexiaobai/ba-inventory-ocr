## 💡 为什么需要这个工具？

在进行学生养成规划、装备升阶与总力战排查时，使用「什亭之匣」（arona.icu）等辅助工具能极大帮助老师理清养成进度。然而：
- 游戏内道具、欧帕兹、技能书、光盘及装备设计图总数高达数百种；
- 每次活动或版本更迭后，手动逐一盘点并在网页端输入往往需要花费半小时以上，且极易输错漏填。

**BA Inventory OCR** 通过屏幕自动化与点阵式 OCR，在 **3 ~ 6 分钟内**全自动完成所有道具及设计图的扫描与数量统计，并智能映射到 SchaleDB 道具数据库 ID，生成标准导入 JSON。

## ✨ 核心特性

- 🛡️ **安全零风险**：
  - 纯前端 UI 模拟与本地离线截图识别，**不注入内存**、**不篡改客户端**、**不修改网络通信**。
  - *(注：港澳台服通信采用客户端生成会话密钥并通过 RSA-4096 公钥加密上报，网络被动解密在密码学上不可行且有封号风险；本工具采用纯视觉路线，稳妥无封号风险。)*
- ⚡ **异步队列引擎（v10 架构）**：
  - **自适应点阵标定**：自动根据角标位置（`x数量`）聚类推算行列间距与缩放比；截图与名称识别区域均锚定游戏窗口矩形，支持窗口化与不同分辨率/缩放。
  - **生产者-消费者并行**：主线程负责极速点击与页面滚动，后台双线程并发运行 RapidOCR 识别，大幅缩短采集时间。
  - **条带哈希去重**：自动跳过空格子与重叠条带，避免冗余识别。
  - **覆盖率到底判定**：底部每个被点击的格子都产出有效读数（或确认重复/重试后放弃）才收工——构造性完整，不靠轮数猜测；首次读取失败的格子自动重试，最终放弃的会列在日志中。
- 🔄 **智能名称映射与繁简兼容**：
  - 直接对接 **SchaleDB TW 区名**（与游戏内名称一致，含 `（三一）` 这类换行显示的学校后缀拼回），技术笔记/战术教育BD 等"同名多物品"家族可精确区分到具体学校与档位。
  - 自动将繁体中文转换为简体规范名称；内置人工校准的别名表（纠正 OCR 常见错字及译名差异，如「乙太/以太」、「沃普赛克/沃尔夫塞格」等）。
  - 支持**道具列表**与**裝備設計圖列表**合并追加。
- 📦 **一键对接什亭之匣**：
  - 直接输出 `什亭之匣库存导入_OCR采集.json`，在什亭之匣「库存管理」点击导入即可立即同步。

## 🚀 使用指南 (使用说明)

### 步骤 1：打开游戏并进入对应页面
1. 启动《蔚蓝档案》游戏客户端；
2. 进入游戏背包的 **「道具」**（或「裝備」）页面；
   > 💡 **提示**：无需特意滑到最顶部，采集器启动后会自动平滑滚回列表最上端。

### 步骤 2：启动自动采集
- **方式 A（推荐）**：直接双击运行仓库根目录下的 **`采集.bat`**。
- **方式 B（命令行）**：在终端运行：
  ```bash
  python ba_queue_collector.py          # 断点续采（保留上次数据）
  python ba_queue_collector.py --fresh  # 清空重扫（旧数据自动备份为 rows2_backup_*.json）
  ```
- 每次运行的控制台输出会同步写入根目录的 **`采集日志.txt`**，采集异常时可回溯定位。

> ⚠️ **重要注意事项**：
> - 脚本会自动检测游戏窗口并置顶；
> - 采集期间（约 3 ~ 6 分钟），**请勿移动鼠标或敲击键盘**，以免打断点击与界面识别；
> - 列表全部采集完成后，程序会自动停止，**随后自动完成名称映射，在 `输出\` 生成导入文件并打开该文件夹**（中间采集数据同时保存在 `rows2.json`）。

### 步骤 3（可选）：追加「裝備設計圖」
1. 道具采集完成后，手动在游戏内切到 **「裝備」** 标签页；
2. 再次双击运行 `采集.bat`（或命令行执行）；
3. 采集器会自动将裝備設計圖数据追加至 `rows2.json` 中。

### 步骤 4（可选）：仅重新生成导入文件（不重扫）
步骤 2 的扫描结束后会**自动**生成导入文件，通常无需此步。若调整了别名表/映射规则后想不重扫重新生成：
- 双击 **`2-生成什亭之匣导入文件.bat`**（完成后自动打开「输出」文件夹）；或终端运行 `python ba_map_items.py`。
- 脚本会自动比对 SchaleDB 的 CN/TW 四份物品库（`cache/` 下缺失时自动从 CDN 下载），并在命令行打印映射统计、数量冲突与待复核清单。

### 步骤 5：一键导入什亭之匣
1. 浏览器访问 [什亭之匣 (arona.icu)](https://arona.icu)；
2. 登录账号并进入 **「库存管理」** 页面；
3. 点击页面右上角的 **「导入」** 按钮；
4. 选择刚刚生成的 `输出\什亭之匣库存导入_OCR采集.json` 并确认；
5. 核对并手动补齐顶部栏目的 **信用点** 与 **青辉石** 数量，保存即可！

### 步骤 6（可选）：图标-名称对齐 `ba_icon_linker.py`
个别道具若因名称识别问题反复无法正确导入，可运行 `python ba_icon_linker.py`（游戏停在道具页，运行方式同步骤 2）：工具逐格抓取「面板名称 + 格子图标」，用图标比对 SchaleDB 图标库得出唯一 ID，产出 `icon_links.json`，映射脚本会自动应用其中高置信链接。需要 `icons/` 图标库（约 1200 张 SchaleDB 图标 webp，与物品 Icon 字段同名）。

## 📌 注意事项与已知边界

1. **货币类数据**：
   - 游戏内的信用点（金币）与青辉石位于游戏界面顶栏，不包含在道具格子里，需在什亭之匣上手动填入。
2. **学生神名文字与各类自选箱**：
   - 港澳台服的学生译名与国服/简中数据库存在一定差异，为了避免串行误映射，这类物品会被自动记录在 `ambiguous.json`（或 `待复核_选择券与神名文字.json`）中供人工核对。通常只需手动开启自选箱或录入即可。
3. **窗口误触与弹窗机制**：
   - 如果在极特殊情况下误触游戏内筛选/设置弹窗，脚本内置了弹窗关键词检测，会自动按 `ESC` 关闭弹窗并重试。
4. **个别道具导入后为 0（游戏内不为 0）**：
   - 多为首次读取失败的偶发情况——重新扫描一遍即可补齐（验证轮会自动重试读取失败的格子，重试 3 次仍失败的会列在 `采集日志.txt` 的「放弃的格子」中，可跑 `ba_icon_linker.py` 图标对齐补救）。
5. **扫描范围 = 当前显示的道具列表**：
   - 游戏道具页存在分类/筛选；若某道具不在当前列表中（部分制造材料、核心类道具可能在其他分类），请先在游戏内切换到对应分类/清除筛选后再扫描。

## 📂 仓库文件说明

```text
ba-inventory-ocr/
├── cache/                     # SchaleDB 物品库（缺失时自动从 CDN 下载）
│   ├── items.min.json         # 道具定义表（CN）
│   ├── equipment.min.json     # 装备/设计图定义表（CN）
│   ├── tw_items.min.json      # 道具定义表（TW，游戏原文名，名称映射用）
│   └── tw_equipment.min.json  # 装备/设计图定义表（TW）
├── legacy/                    # 已归档的实验方案（图标匹配扫描器，思路由 ba_icon_linker.py 继承）
│   └── ba_icon_scanner.py
├── tests/                     # 映射/解析逻辑回归测试（不需要游戏窗口）
│   └── test_mapping.py
├── .gitignore                 # Git 忽略配置（个人游戏数据与本机配置均不入库）
├── requirements.txt           # Python 依赖清单（实测锁定版本）
├── 采集.bat                   # 一键运行采集脚本
├── 2-生成什亭之匣导入文件.bat # 可选：不重扫时单独重新生成导入 JSON（采集结束也会自动生成）
├── ba_queue_collector.py      # 核心采集器（点阵巡航、多线程队列、覆盖率停止判定、RapidOCR）
├── ba_map_items.py            # 数据映射与转换器（TW/CN 双区匹配、别名纠错、歧义护栏、导出 JSON）
├── ba_icon_linker.py          # 可选：图标-名称对齐工具（识别不出的道具用图标比对补救，需 icons/ 图标库）
├── local_python_path.txt      # 可选：本机 Python 解释器路径覆盖（不入库）
├── recover_local.json         # 可选：个人人工校准数量（不入库，键为 item_<Id>）
├── 采集日志.txt               # 每次采集的控制台日志（自动生成，不入库）
└── README.md                  # 项目说明文档
```
